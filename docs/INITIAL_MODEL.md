# Начальная модель и редактор вокселей

Основной маршрут: три шага слева в модуле 3D-моделирования. Все операции подготовки открываются на шаге 2 кнопкой «Редактор вокселя…» в отдельном окне.
Изменения применяются сразу; «Готово» возвращает к основному маршруту.
Справочник кнопок и сценарии ZMAP/CSV для трёх физических режимов —
в начале [руководства по 3D-моделированию](INVERSION.md).

Во вкладке «03 · 3D-моделирование» блок «02 · Начальная модель» выбирает источник
геометрии и свойств. Модель и наблюдения — независимые данные. Поле нужно для
моделирования, но готовый воксель можно загрузить и просмотреть без наблюдений.

## Константа или готовая модель

- «Константа на новой сетке»: область строится по наблюдениям, запасу площади,
  Nx/Ny/Nz и верху/низу. Свойства берутся из «Начальное значение».
- «Загруженная / отредактированная модель»: используются её собственные грани,
  значения и активные ячейки. Nx/Ny/Nz не изменяют эту модель при запуске.
- «Использовать результат последнего моделирования» переносит результат в начальную
  модель новой задачи. Это новый запуск решателя, не восстановление состояния
  прежнего алгоритма. Результат NPZ также можно загрузить через импорт модели.

Эффективная плотность подаётся в g/cm³; фон автоматически не вычитается. χ — SI;
JE/JN/JD — A/m. Отрицательные эффективные плотности допустимы. Начальные активные
свойства должны лежать в выбранных границах: интерфейс требует явно исправить
границы или применить операцию ограничения, вместо молчаливого изменения модели.

## Форматы

| Формат | Правила |
|---|---|
| UBC / Geosoft UBC | Пара `.msh`/`.mesh` и `.mod`/`.den`/`.sus`. Прямоугольная tensor-сетка, включая неравномерные размеры и `N*size`. Octree не поддерживается. |
| Geosoft `.geosoft_voxel` | Чтение через официальный GX Python/runtime на Windows в отдельном процессе. Одного Python-пакета недостаточно. См. установку ниже. |
| VTK / VTR / VTI | Осевая RectilinearGrid/ImageData, свойства в cell_data. Z — высота Up. Выберите массив при импорте. Повороты и произвольная unstructured-сетка пока не импортируются. |
| XLSX / CSV / TXT центров | `East, North, Down, Property` или `East, North, Up, Property`. Для вектора: `JE, JN, JD` вместо Property. Центры равномерны, минимум 2 по оси; отсутствующие ячейки неактивны. Для неоднозначной геометрии используйте UBC/VTR. |
| NPZ GeoGarModel | Начальная модель либо результат моделирования; сохраняются свойства, CRS, маска, обрезанные грани и история операций. |

UBC: начало mesh — юго-западный верхний угол **East, North, Elevation** в метрах.
Сначала меняется глубина, затем East, затем North. Dummy не универсален: вводите
его явно при импорте (например, Geosoft export часто использует −1). Dummy нельзя
автоматически приравнивать к −1, поскольку это может быть реальная плотность.

Кнопка JE/JN/JD запрашивает три скалярных файла в порядке East, North, Down.
Грани и CRS должны совпадать. JD положительна вниз; автоматического изменения
знака вертикальной компоненты из других соглашений нет.

У всех источников координаты должны быть в одной системе, одном локальном
начале и одном вертикальном нуле. Выбор EPSG маркирует данные; не выполняет
перепроецирование, добавление зонального префикса или сдвиг East.

## Geosoft GX (в процессе разработки)

Официальные материалы: [GX Python](https://github.com/GeosoftInc/gxpy),
[GX runtime](https://github.com/GeosoftInc/gxcore/releases),
[экспорт Geosoft в UBC](https://help.seequent.com/Oasismontaj/2023.2/Content/gxhelp/e/Geosoft_GX_VoxUtils_ExportVoxToUBC.htm).

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[geosoft]"
# Для распакованного runtime: каталог, содержащий bin/geodist.dll
$env:GEOGARMODEL_GX_REDIST = 'C:\путь\GeosoftRedist'
.\.venv\Scripts\python.exe -m geogarmodel
```

Без этой переменной GX использует штатно установленный runtime. Сборки Python,
GX Python и runtime должны быть совместимы. Нативный импорт изолирован от Qt:
его сбой выводит ошибку, а не закрывает GeoGarModel. Чтение ограничено 180 с.
Если GX не запускается, экспортируйте в Oasis montaj через Voxel → Conversions →
Voxel to UBC и загрузите оба файла. Бинарный формат не декодируется догадками.

Локально пакет GX 2026.1 и официальный minimal runtime установлены для проверки,
но GX завершился с кодом 1 при открытии предоставленного файла; его геометрия
и свойства пока не подтверждены. Поддержка этого конкретного native-файла
остаётся непроверенной; для проверки модели нужен UBC-экспорт либо рабочая GX-среда.

## Предварительный просмотр и операции

«Предпросмотр модели и поля» показывает горизонтальный и вертикальный срезы,
наблюдённую карту, размеры и диапазон свойств. Большое поле отображается выборкой
до приблизительно 20 тысяч точек; это не меняет данные расчёта. «Показать начальную
модель в 3D» отображает действительную геометрию активных призм.

Операции действуют на активные ячейки, создают новую модель и записывают историю:
константа, прибавление, умножение, ограничение диапазона, нормальное/равномерное
распределение с seed и линейный градиент `a+b*Down`. Для вектора можно выбрать
все компоненты или одну. Есть отмена последней операции и сохранение NPZ.
Прямоугольная обрезка задаётся Emin,Emax,Nmin,Nmax,Dmin,Dmax, в метрах; сохраняются
пересекающиеся части призм.

## Обрезка трехмерной модели по произвольной поверхности

1. Загрузите или создайте модель; выберите «Обрезать по поверхности…».
2. Загрузите ZMAP/NPZ-карту поверхности либо таблицу East,North,Down/Up.
3. Выберите метры Down (глубина) или Up (высота) относительно нуля модели.
4. Выберите, что оставить: 3Д модель ниже поверхности или выше.
5. Просмотрите результат в 3D, затем сохраните NPZ или запускайте моделирование.

Например, модель 0–30 км и фундамент глубиной 5 км: «ниже» оставляет 5–30 км,
«выше» оставляет 0–5 км. Вырезанные ячейки неактивны и не восстанавливаются
решателем заново. Пересечённые ячейки становятся призмами уменьшенной высоты:
эти реальные размеры используются в прямом поле и экспорте, а не только в картинке.

Поверхность линейно интерполируется в XY-центрах колонок; внутри горизонтальной
ячейки она считается плоской. Это аппроксимация вертикальными призмами, а не
точное пересечение наклонного треугольника с вокселем. Для лучшей детализации
уменьшайте горизонтальный шаг. Поверхность должна покрывать все активные колонки;
экстраполяции за её выпуклую оболочку нет. При пропусках внутри карты сначала
подготовьте достоверную сплошную поверхность. Сглаживание не связывает неактивные
и активные ячейки. Полная обрезанная модель сохраняется в NPZ; VTK-экспорт — VTU,
для обычной прямоугольной модели — VTR. Импорт обрезанного VTU пока не поддержан.

## "Перенос на другую сетку" или "Изменение разрешенности исходной 3Д модели"

Нужен только при смене разрешения/области: например, исходные 500-метровые ячейки
пересчитать на 1000-метровые для ускорения. Задайте новую сетку Nx/Ny/Nz, верх/низ
и запас относительно площади наблюдений; нажмите «Перенести…».

`nearest` берёт свойство содержащей исходной ячейки, `linear` интерполирует по
центрам и сглаживает переходы. Внешняя половина краевой ячейки при linear использует
линейное продолжение значений центров до грани. За исходной областью и внутри
исключённых призм целевые ячейки неактивны. Масса, магнитный момент и поле могут
измениться: консервативное интегрирование перекрытия объёмов не реализовано.
Для обрезанной границы маска переносится по центрам новых ячеек; после переноса
примените исходную поверхность заново, чтобы вновь обрезать пересечённые призмы.
