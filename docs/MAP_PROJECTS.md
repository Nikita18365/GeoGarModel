# Проекты карт и трансформанты

## Проект магнитных или гравиметрических карт

1. Откройте **Проект → Создать…**, введите своё название, например
   «Магнитное поле — Анабар», и выберите СК проекта, например
   `EPSG:20918 | GSK-2011 / Gauss-Kruger zone 18`. Для существующего проекта
   используйте **Проект → Система координат…** или кнопку **СК проекта…**.
2. На шаге **1 · Карта** загрузите сетки GRD/ZMAP/DAT/NPZ или таблицу XYZ.
3. При необходимости откройте **СК и параметры слоя…**: единицы поля (nT, mGal
   и другие), координат и систему координат. При заданной СК проекта изменение
   исходной СК карты вызывает её перепроецирование в СК проекта. Единицы поля
   автоматически не пересчитываются. Для трансформант требуются метрические координаты.
4. Выберите **Проект → Сохранить**. Общий файл `.ggproject` содержит сами сетки,
   векторные контуры, названия, порядок, видимость, оформление и текущий масштаб,
   а также данные и результаты ML/Optuna и 3D-моделирования.
   Для повторного открытия исходные файлы не нужны.
5. Выберите **Проект → Закрыть**, затем создайте другой проект, например
   «Аномалии гравитационного поля в редукции Буге». При несохранённых изменениях
   программа предложит сохранить их, отбросить или отменить закрытие.
6. Для возвращения выберите **Проект → Открыть…** и нужный `.ggproject`.

Проект общий для всех трёх модулей. Старые файлы `.ggmaps` также открываются,
но содержат только те данные, которые были сохранены в них ранее.
Подробно: [что сохраняет общий проект](PROJECTS.md). Переключение проектов во
время фонового расчёта заблокировано, чтобы результаты не попали в другой проект.

## Слои: что показывать и в каком порядке

- Значок рядом с названием показывает тип слоя: цветная карта с изолиниями —
  числовая сетка (включая рассчитанные трансформанты); линия, полигон и точка —
  SHP/GeoJSON и другие векторные данные; пиксельная мозаика — растровое изображение.
  Значки назначаются автоматически при импорте и открытии проекта. Список остаётся
  единым, чтобы свободно менять порядок наложения слоёв независимо от их типа.
- Галочка слева включает отображение карты или векторного контура. Можно
  одновременно включить несколько слоёв. Выделение строки выбирает слой для
  оформления, экспорта или расчёта; это отдельное действие от галочки видимости.
- Верхняя строка списка отображается впереди нижних. Перетаскивайте строки мышью,
  чтобы изменить порядок, либо используйте правую кнопку → **Выше / Ниже**.
  Перемещение сохраняет данные, оформление и галочку слоя.
  Непрозрачная верхняя карта перекроет нижнюю там, где
  у неё есть значения; пропуски прозрачны. Для смешивания задайте
  **3 · Вид → Цветовые элементы → Непрозрачность слоя**, например `0,5`.
- Переименуйте слой двойным щелчком, клавишей F2 или через правую кнопку мыши →
  **Переименовать**. Для удаления выделите строку и нажмите Delete, пока фокус
  находится в списке, либо выберите правой кнопкой мыши → **Удалить**.
  Исходный файл на диске при этом не удаляется.
- Оформление хранится отдельно для каждой карты. Выберите карту в списке,
  перейдите на **3 · Вид** и измените нужный параметр. Изолинии и отмывка не
  сбрасываются при смене палитры, диапазона или названия; текущий масштаб
  сохраняется. Вернуть общий охват можно командой
  **Проект → Вписать все видимые карты**.

## Свойства слоя

В дереве **1 · Карта** нажмите правой кнопкой мыши на карту, растр
или векторный слой и выберите **Свойства…**. Окно только для чтения;
кнопка «Копировать всё» переносит сведения в буфер обмена. Расчёт статистики
использует полные данные текущего слоя, а не уменьшенное изображение
быстрого просмотра.

- Общие сведения: название, тип, расширение исходного файла, полный путь
  при импорте, исходная СК (если сохранена) и текущая СК с единицами осей.
  Для расчётных слоёв и старых проектов без пути указывается отсутствие
  информации; исходный файл для просмотра свойств не нужен.
- Числовая карта: xmin/xmax/ymin/ymax по координатам узлов, x_space/y_space,
  Nx/Ny, общее число узлов, число конечных значений и пропусков, покрытие,
  min/max, среднее, медиана, стандартное отклонение (по совокупности),
  единицы поля. NaN исключаются из статистики. Для карты из XYZ дополнительно
  указаны исходные столбцы X/Y/Z и размеры таблицы.
- Растр: границы внешних краёв пикселей, ширина и высота, число пикселей,
  размер пикселя по X/Y, представление RGBA, тип данных, количество
  видимых и прозрачных пикселей, покрытие, число ручных опорных точек.
  Это свойства изображения внутри проекта после привязки/перепроецирования,
  а не оригинальных спектральных каналов или физических значений GeoTIFF.
- SHP/GeoJSON: границы по вершинам, количество хранимых объектов и пустых
  геометрий, перечень типов, число точек, линейных и полигональных частей
  (включая Multi* и GeometryCollection), число записей координат/вершин.
  Замыкающая вершина кольца учитывается как отдельная запись. Атрибуты DBF
  и свойства GeoJSON существующий импорт не сохраняет, поэтому статистика
  по ним не выводится.

Пути и исходная СК сохраняются в .ggproject и .ggmaps без изменения версии
формата; не восстанавливаются из одного лишь имени слоя. Путь означает
источник импорта, а не путь к новому файлу экспорта. Текущие размеры и
статистика могут отличаться от исходного файла после перепроецирования
или построения карты из XYZ. Переименование слоя не меняет путь.

## Экспорт выбранного слоя · 4 · Файл

В дереве **1 · Карта** выделите числовую карту или карту, созданную из таблицы
XYZ, затем откройте **4 · Файл**. Слой может быть скрыт галочкой: важен именно
выбор строки. Доступны NPZ, XLSX, CSV, TXT, Geosoft Binary GRD, ZMAP+ (Petrel)
и ArcGIS Float Grid (FLT). Цветные сокращения слева: голубой NPZ,
зелёные XLSX/CSV/TXT и золотые GRD/ZMAP/FLT. Для SHP/GeoJSON и изображений эти семь форматов
не предлагаются: они предназначены для числового поля или таблицы.

- Обычная числовая карта: сеточные форматы записывают её текущие координаты
  и значения; табличные форматы сохраняют все узлы в трёх столбцах East, North, Z
  (включая пустые значения Z).
- Карта из XYZ: XLSX, CSV и TXT сначала предлагают всю исходную таблицу
  (все столбцы в исходном порядке, включая нечисловые) либо только выбранные
  East, North, Z. Табличный экспорт не интерполирует и не перепроецирует
  исходные строки. TXT разделён табуляцией, CSV — запятыми; оба UTF-8 BOM.
- Для NPZ, GRD, ZMAP и FLT из XYZ выберите три разных числовых столбца.
  Текущая тройка экспортирует текущую сетку; для другой тройки строится
  отдельная сетка в СК проекта, без изменения карты и исходной таблицы.
  Полная равномерная прямоугольная сетка восстанавливается без интерполяции;
  иначе применяется линейная интерполяция на размере текущей сетки.
- NPZ сохраняет метаданные; GRD — несжатый Geosoft v2 double, ZMAP —
  текстовый ZMAP+ с координатами узлов, FLT — little-endian float32 плюс
  обязательный HDR. Для трёх внешних сеточных форматов при наличии СК
  создаётся PRJ рядом с файлом. Внешняя программа может потребовать
  указать СК отдельно. Знак Z не меняется. Для FLT с разными шагами X и Y
  нужно подтвердить интерполяцию на квадратную сетку; при отказе экспорт
  отменяется. XLSX ограничен 1 048 575 строками данных (с учётом заголовка)
  и 16 384 столбцами; для более крупных таблиц используйте CSV/TXT.

### Точность экспорта

X/Y записываются с точностью до шести знаков после десятичной точки во всех
семи форматах. При экспорте всей таблицы округляются только два столбца,
назначенные X/Y для выбранного слоя; остальные признаки сохраняются. При
экспорте выбранной тройки ограничение применяется к её East/North. Исходный
слой и таблица не меняются. Для регулярных сеток округляются начало и шаг
осей, чтобы сохранить равномерность; на длинной оси отклонение может
накапливаться до 0,5 микроединицы за интервал. Слишком малый шаг, который
после округления становится нулём, не экспортируется. При нечётном шаге
в микроединицах FLT записывает XLLCENTER/YLLCENTER вместо XLLCORNER/YLLCORNER.

Z не округляется намеренно: NPZ/GRD хранят float64, ZMAP использует
обратимо читаемое представление float64 (25 символов на поле), CSV/TXT —
обычную сериализацию исходных чисел, XLSX — числовые ячейки в пределах
точности Excel. FLT хранит float32 и поэтому ограничен примерно 7–8
значащими цифрами. Первоначальные текстовые хвостовые нули и цифры,
потерянные при импорте, восстановить нельзя. При интерполяции Z является
расчётным значением, а не исходной строкой.

## Общая система координат проекта

Выберите метрическую СК проекта при создании либо кнопкой **СК проекта…**.
Все вновь импортируемые карты и векторы автоматически преобразуются в неё.
Смена СК существующего проекта перепроецирует все его слои, включая скрытые.
Если преобразование какого-либо слоя не удалось или пользователь отменил ввод
исходной СК, замена данных проекта не выполняется.

СК проекта обязательна перед импортом данных. СК источника читается из метаданных
NPZ, `.prj` у SHP и сеток, либо из GeoJSON. Если она не найдена, программа
использует СК проекта и сообщает об этом в строке состояния. Это явное допущение:
если реальные координаты файла относятся к другой СК, включите **Уточнять
исходную СК при импорте** и выберите её самостоятельно. Например, долгота/широта
WGS84 требуют EPSG:4326. Согласуйте зональный префикс East с параметрами проекции.

Растры пересчитываются линейной интерполяцией на регулярную сетку в СК проекта.
Количество узлов по каждой оси сохраняется (не менее трёх при перепроецировании).
Вне преобразованной области остаются пропуски; значения не экстраполируются.
Интерполяция может сгладить пики и расширить пропуски рядом с NaN. Это изменение
данных сетки, а не только подписей осей; поле не пересчитывается на новую высоту.
При той же исходной и целевой СК свойства копируются без интерполяции.

Координаты SHP/GeoJSON преобразуются напрямую без растрирования. Файлы-источники
на диске не изменяются; `.ggproject` сохраняет преобразованные данные и СК проекта.
При многократных сменах СК растр интерполируется повторно; для сохранения качества
выбирайте рабочую СК заранее и храните исходные файлы отдельно.

Цветовая шкала справа относится к верхней видимой карте; у нижних карт сохраняется
собственная нормировка. Старые `.ggmaps` открываются: общую СК можно назначить
через **СК проекта…**. В рабочем пространстве без явной настройки используется СК
первой карты, если она известна.

При импорте XYZ по умолчанию используется СК проекта; её можно уточнить указанной
галочкой. Отдельно выбирается порядок первых двух столбцов (East/North или
North/East). Настройки координат ML-модуля при этом не используются.

## Быстрый просмотр и оформление для экспорта

**Быстрый просмотр** использует PyQtGraph. Перемещение — перетаскивание мышью,
масштабирование — колесо. Растры, контуры SHP/GeoJSON и изолинии находятся в
постоянной графической сцене. При навигации растры выбираются только для видимой
области в разрешении экрана; после увеличения появляются более подробные данные.
Для изображения используется копия float32, исходные значения и точность расчётов
сохраняются. По умолчанию **Плавное изображение (рекомендуется)** интерполирует
значения перед назначением цветов; при уменьшении выполняется выборка площади
экранного пикселя вместо пропуска каждой N-й ячейки. Пропуски сохраняются. Чтобы
увидеть исходные ячейки, отключите эту галочку. Старые проекты однократно переходят
на плавное отображение; выбранный затем режим сохраняется. Это работает на CPU
без CUDA и Geosoft API. Предварительно рассчитанные
изолинии и тени при обычном перемещении не пересчитываются.

**Оформление и экспорт** использует Matplotlib: здесь находятся итоговая компоновка,
северная стрелка, масштабная линейка и подписи для печати. Лист, фон карты и цветовой
шкалы белые, подписи, оси, стрелка и обозначения линейки тёмные. Тема остальных
модулей не изменяется. PNG/PDF/SVG получают белый фон листа. Плавное отображение
использует билинейную интерполяцию значений перед раскраской, включая экспорт;
цветовые зоны при этом сохраняют заданные границы. Такое оформление само по себе
не удостоверяет соответствие конкретному ГОСТ: формат листа, рамка, шрифты и
обязательные реквизиты определяются требованиями к конкретному документу.
Кнопки панели Matplotlib
работают с этой вкладкой; на быстрой вкладке используйте мышь. Общий заголовок,
палитра, видимость и порядок слоёв применяются к обоим видам. Навигация мышью на
быстрой вкладке переносит диапазоны X/Y в экспортируемую карту. Изменение оформления
пока перестраивает экспортный график; скорость такого изменения отличается от
скорости обычного перемещения карты.

## Geosoft Binary Grid

Нажмите **Открыть GRD / ZMAP / DAT / NPZ / FLT**, выберите `.grd`. Чтение не требует
установки или лицензии Geosoft. Поддерживаются числовые GRD v2: целые и вещественные
значения, сжатые и несжатые блоки, пропуски dummy и масштабирование из заголовка.
Порядки хранения ±1 поддерживаются; RGB-сетки и Surfer GRD этим читателем не читаются.
Повёрнутая сетка переносится линейной интерполяцией на регулярную XY-сетку, что
фиксируется в истории. Исходный GRD не изменяется.

Соседний `.prj` читается автоматически. Бинарный `.gi` сохраняется как запись о
сопутствующем файле в истории, но его внутренняя СК **не декодируется**: без `.prj`
используется СК проекта либо ручной выбор. Одного наличия `.gi` недостаточно для
подтверждения правильной СК. В предоставленном примере GRD начало сетки равно
0, 0, шаг 500 м, размер 1001×773; это значения заголовка, они не сдвигаются по
догадке о местоположении.

## Раздел «3 · Вид»: раскрывающиеся панели

Настройки сгруппированы в семь независимых панелей. Нажмите заголовок
со стрелкой, чтобы раскрыть или свернуть его прямо в левой панели.
По умолчанию открыты «Цветовые элементы», остальные разделы свёрнуты.
Можно открыть несколько панелей одновременно; сворачивание не сбрасывает
настройки, не выключает изолинии или рельеф и не меняет текущий слой.

| Панель | Настройки |
| --- | --- |
| Цветовые элементы | Палитра, библиотека, нормировка, диапазон, инверсия, зоны, сглаживание, непрозрачность |
| Изолинии | Включение, сечение, цвет, толщина, подписи |
| Теневой рельеф | Включение, положение солнца, азимут, высота, интенсивность, усиление |
| Оси и географическая сетка | Подписи осей, режим сетки, формат углов, шаг, толщина и цвет |
| Масштабная линейка | Включение, единицы, шаг, число делений, подпись СК |
| Заголовок и компоновка | Общий заголовок, автокомпоновка белого листа |
| Шрифты и подписи | Независимое оформление девяти текстовых элементов |

В списке палитр доступны сразу все встроенные и ранее импортированные
шкалы с цветовыми миниатюрами. Для поиска и импорта остаётся кнопка
«Библиотека палитр…». При загрузке любой новой числовой карты, включая
XYZ и расчётные трансформанты, применяется **geophysics/clra_128.tbl**.
Инверсия и дискретные зоны выключены для новой карты. Старые карты,
включая восстановленные из проекта, сохраняют свои палитры и настройки.
Если встроенная шкала недоступна, используется viridis.

## Оформление публикационной карты

- **Изолинии:** «Подписывать каждый N-й уровень» регулирует частоту подписей
  по уровням (1 — все уровни, 2 — через один); сечение и геометрия не меняются.
- **Масштаб над картой:** колесо мыши приближает и отдаляет карту относительно
  положения курсора по обеим осям. Штатная кнопка масштабирования Matplotlib
  позволяет выбрать прямоугольную область, а «Домой» возвращает полный охват
  видимых слоёв. Ручное перемещение карты остаётся доступным; равный аспект
  и центральное выравнивание рамки сохраняются. 1:N — оценка масштаба в
  проекции на листе, не калиброванный физический масштаб монитора.
  Отдельное поле процентов и кнопка 100 % не используются.
- **Цветовые элементы:** цветовая шкала вертикальная (Y, справа) или
  горизонтальная (X, снизу справа от масштабной линейки). Вертикальная шкала
  привязана к правой грани фактической рамки карты. Если длинная линейка,
  подпись СК или крупный шрифт не оставляют места, горизонтальная шкала
  автоматически переносится на отдельную строку ниже. Шкала относится к
  верхней видимой карте. Её числовые значения и подпись единиц оформляются
  независимо; прежний общий стиль копируется в оба при открытии старого проекта.
- **Масштабная линейка:** единицы и подпись СК центрированы по длине линейки;
  суффикс «(пользовательские параметры)» удаляется только из отображаемой подписи.
- **Перемещать элементы:** включите одноимённую кнопку на панели оформления
  и перетащите левой кнопкой заголовок, подпись оси X/Y, цветовую шкалу,
  масштабную линейку целиком или стрелку севера. Отключите режим для обычной
  навигации. Смещения сохраняются в проекте отдельно от координат карты;
  для двух ориентаций цветовой шкалы они независимы. «Сброс позиций» возвращает
  автоматическую компоновку. Автоматическая подгонка внешних полей не
  переопределяет ручные позиции. Отдельные числа изолиний/делений не перемещаются.
- **Шрифты и подписи:** выберите один из девяти элементов, задайте гарнитуру,
  размер в пунктах, жирность, курсив и цвет. Предпросмотр показывает
  выбранный стиль; «Применить к элементу» обновляет только его.
  «Сбросить элемент» возвращает стандартное оформление. Настройки общие
  для текущего листа и сохраняются вместе с ориентацией шкалы в проекте.
  Список содержит реальные гарнитуры, распознаваемые Matplotlib. Системные
  псевдонимы Windows (например, MS Shell Dlg 2) и недоступные гарнитуры из
  старых проектов автоматически заменяются доступным шрифтом (Tahoma или
  Segoe UI для MS Shell Dlg 2, иначе DejaVu Sans), без отключения предупреждений.
- **Экспорт изображения:** кнопка сохранения в «Оформление и экспорт»
  предлагает PNG, JPEG, TIFF, PDF и SVG, 72–1200 DPI, качество JPEG,
  прозрачность и отступ в миллиметрах (по умолчанию 0). Обрезка по
  tight bounding box сохраняет рамку, подписи, север и линейку, а не
  пустые внешние поля. Для PDF/SVG DPI задаёт разрешение растровых частей.
  Ограничение растрового экспорта — оценочно 100 млн пикселей. Экспорт
  живого листа выполняется в GUI-потоке для корректной отрисовки динамических
  элементов; при высоком DPI возможна пауза интерфейса.

## Библиотека цветовых палитр

1. Выберите карту → **3 · Вид → Цветовые элементы → Библиотека палитр…**.
2. Все **143 палитры исходного архива и дополнительная #GRAV.TBL** уже включены
   в программу. Папки сохранены как категории: `heat map`, `geophysics`,
   `topography`, `monochromatic`, `miscellaneous`. Вручную загружать архив не нужно.
   Для своих дополнительных файлов остаётся **Импорт TBL / ZON / LUT / ZIP…**.
3. Отфильтруйте категорию, тип файла или название. В каждой строке показаны
   **раскраска, имя и число цветов**. Двойной щелчок либо **OK** применяет выбор.
4. Включите при необходимости **Дискретные цветовые зоны**, задайте число зон,
   **Обратить палитру**, **Плавное изображение (рекомендуется)**. Нормировка **Равная площадь
   (гистограмма)** распределяет цвета по квантилям значений поля.
5. У ZON можно включить **Использовать границы значений из ZON**: это абсолютные
   значения поля, а не проценты; в этом режиме используются исходные цвета и
   границы ZON вместо автоматического диапазона и числа зон. Первая нижняя граница
   восстанавливается по разности первых двух верхних границ. Уточните единицы поля.

Поддерживаются RGB и CMYK TBL, CMY/CMYK ZON и ER Mapper LUT с 8/16-битными цветами.
Встроенная библиотека поставляется с приложением, включая wheel и обычную
установку через pip. Дополнительно импортированные палитры хранятся в локальных
настройках пользователя. Цвета и
границы палитры выбранной карты входят в `.ggproject`; при переносе проекта доступ к
исходному архиву не нужен. На другом компьютере встроенный каталог доступен сразу.

## Как рассчитать трансформанту

Выделите исходную карту, откройте **2 · Расчёт**, выберите метод. Показываются
только параметры, которые относятся к выбранной операции.

| Трансформанта | Что задавать |
| --- | --- |
| Производные X/Y, первая и вторая вертикальные производные | Дополнительных параметров нет: нажмите «Рассчитать → новый слой». |
| Горизонтальный градиент, аналитический сигнал, Tilt | Дополнительных параметров нет. |
| Продолжение вверх, локальное поле после продолжения | Высота продолжения в метрах. |
| Полиномиальный тренд, локальное поле после вычитания тренда | Степень тренда 1–3. |
| Гауссов низко-/высокочастотный фильтр | Длина волны фильтра в метрах. |

Результат появляется новым верхним слоем. Исходная карта остаётся в проекте.
Для FFT используется прежнее дополнение краёв на 25%; отдельный ввод не требуется.
Методика расчёта и влияние краёв описаны в [основном руководстве](MODERNIZATION.md).

## Калькулятор гридов · 2 · Расчёт

Загрузите числовые карты в проект, затем откройте **2 · Расчёт →
Операции над сетками → Калькулятор гридов…**. Введите число операндов
(от одного до количества числовых карт проекта) и выберите карты A, B, C…
После Z используются AA, AB и т. д. Векторные слои и изображения исключены.
Выделенная карта по умолчанию становится A. Галочка видимости значения не имеет.

Готовые операции: SUM (сумма), SUB (последовательное вычитание),
MUL (произведение), DIV (последовательное деление), MEAN, MIN, MAX,
AND, OR, XOR, NOT, ABS, SQRT, LOG10. NOT, ABS, SQRT и LOG10 — для одной карты;
остальные готовые операции требуют минимум двух. Вычитание и деление
выполняются слева направо: A − B − C, A / B / C.

В режиме FORMULA можно комбинировать арифметику, числа, сравнения,
логические операции и функции, например:

- `A + B - C`, `(A+B)/2`, `sqrt(A**2+B**2)`;
- `(A > 100) & (B < 20)`, `(A != 0) or (B > 0)`;
- `where(A > 0, B, C)`, `clip(A, -10, 10)`,
  `abs(A)`, `log10(A)`, `sum(A,B,C)`, `mean(A,B,C)`.

Поддерживаются +, -, *, /, **, %, сравнения <, <=, >, >=, ==, !=,
and/or/not, &, |, ^, ~; функции abs, sqrt, log, log10, exp, sin, cos,
clip, where, min, max, sum, mean. Ненулевые конечные значения истинны,
логический результат записывается как 1 или 0. Формулы ограничены
4096 знаками и 512 узлами синтаксиса; произвольный Python-код не исполняется.

**Сетки:** по умолчанию координаты всех используемых карт должны совпадать.
При отличающемся шаге, положении узлов или размере выберите
«Линейная интерполяция на A»: остальные карты будут выборочно
интерполированы в узлы A в той же СК, без экстраполяции. Геометрия результата
всегда равна A. Неизвестная СК допускается только когда она не задана у
всех используемых карт, и единицы координат совместимы.
Пропуск любой используемой карты даёт пропуск результата, включая сравнения
и логические операции. Деление на ноль, недопустимый логарифм и бесконечности
также дают NaN; если конечных узлов не осталось, новая карта не создаётся.
В where вычисленное неопределённое значение в невыбранной ветви не влияет
на итог, но исходные пропуски операндов не подменяются нулями.

Укажите при необходимости суффикс имени и единицы результата. Для суммы,
разности, среднего, минимума и максимума одинаковые известные единицы
предлагаются автоматически; для смешанных единиц и произвольных формул
пользователь определяет их сам. Для логических операций единица — 1.
Калькулятор не преобразует физические единицы полей автоматически.
Нажмите «Рассчитать → новый грид»: создаётся отдельная карта с префиксом
операции, например SUM_field_A_field_B, или FORMULA_... . Одноимённый
результат получает номер (2), (3) и т. д. Источники не изменяются.
Расчёт выполняется в фоновом потоке приложения блоками строк с индикатором
прогресса, а результат, формула, операнды и режим согласования сеток
сохраняются в истории карты и общем проекте .ggproject.
Новый слой можно использовать в следующей формуле и экспортировать
в любой из семи числовых форматов.

## Изолинии и оформление

Выделите нужную карту → **3 · Вид** → включите **Изолинии**. Появятся:

- **Сечение изолиний** — шаг в единицах поля, например `10` для карты в nT
  означает уровни … −20, −10, 0, 10, 20 … nT. `Авто` выбирает уровни автоматически.
- **Цвет изолиний** — нажмите «Выбрать цвет…» и выберите оттенок в палитре.
  Образец текущего цвета показан прямо на кнопке.
- **Толщина изолиний** — ширина линий; отдельная галочка включает подписи значений.

Если шаг даёт больше 1000 уровней, увеличьте его. При крупном шаге и отсутствии
уровней внутри диапазона карты линии не рисуются. Для больших сеток построение
изолиний использует прореживание до приблизительно 512 узлов по каждой оси.

Палитра, нормировка, диапазон, теневой рельеф и непрозрачность применяются
к выбранной карте. **Общий заголовок** один для всего проекта и не меняется при
выборе другого слоя. Если поле пустое, используется название проекта. Названия
строк в списке слоёв по-прежнему помогают различать исходные карты; они не
подставляются в заголовок графика. Общий заголовок сохраняется в `.ggproject`.
Изменения переключателей и числовых полей отображаются сразу;
текстовое поле применяется после завершения редактирования (Enter или выход из
поля). Кнопка «Применить оформление» также доступна.

## Configure subplots и экспорт

По умолчанию включена **3 · Вид → Заголовок и компоновка → Автокомпоновка белого листа**. Поля подбираются
по размеру окна и габаритам названия, осей, шкалы, севера и масштабной линейки.
Карта вписывается с сохранением пропорций и текущего координатного охвата.
При уменьшении окна компоновка пересчитывается. Если заданная длина масштабной
линейки превышает 75 % ширины карты, её фактический шаг автоматически уменьшается
до подходящего значения; количество делений сохраняется, подписи показывают
фактические расстояния. Не следует путать это с растяжением координатных осей.

В панели над графиком откройте **Configure subplots** и задайте поля
`left`, `right`, `top`, `bottom` и промежутки `wspace`, `hspace`. Значения
сохраняются автоматически на этом компьютере и применяются в ручном режиме к картам всех
проектов, в том числе после перезапуска приложения. Переключение слоёв,
оформление и экспорт изображения не сбрасывают выбранные поля.

Текущие числовые диапазоны X/Y при настройке полей сохраняются. Доступная площадь
рисования может измениться из-за новых отступов; это не возврат к полному охвату.
Чтобы выбрать другой участок, используйте навигацию; чтобы восстановить полный
охват — «Домой». Если выводите линейку и подпись СК, оставьте для них достаточное
нижнее поле. В ручном режиме автоматическое размещение не переопределяет сохранённые настройки.

Экспортируйте изображение кнопкой дискеты в той же панели. Оно содержит общий
заголовок, текущий состав видимых слоёв, выбранную область и сохранённые поля.
Настройки полей используются всеми картами и сохраняются в общем `.ggproject`,
включая перенос на другой ПК. Старые `.ggmaps` без этих настроек используют
локальные настройки Configure subplots. Открытие Configure subplots
переключает лист в ручной режим. Чтобы снова подбирать поля автоматически, включите
**Автокомпоновка белого листа**. Признак режима сохраняется в проекте.

## Проекционные и географические оси

Откройте **3 · Вид → Оси и географическая сетка**:

- **Подписи осей**: X/Y в метрах либо долгота/широта. При выборе градусов
  координаты подписей рассчитываются в географической СК, на которой основана
  проекция проекта. Растр не перепроецируется, его значения не интерполируются
  повторно. У наклонных меридианов и параллелей градусные отметки ставятся там,
  где они пересекают нижнюю и левую рамки карты.
- **Географическая сетка**: нет, кресты, пунктирные линии, сплошные линии,
  только засечки по рамке. Линии соответствуют преобразованным меридианам и
  параллелям, поэтому могут быть искривлены относительно прямоугольной XY-сетки.
- **Шаг долготы / широты** задаются отдельно. Ноль означает автоматический подбор.
  Формат **Десятичные градусы**: 0.5 = 30 минут. Формат **ГГГ.ММСС**:
  0.3015 = 0°30′15″, 1 = 1°. Минуты и секунды должны быть меньше 60.
- **Толщина линий, мкм** — физическая толщина при экспорте (100 мкм ≈ 0,283 pt).
  **Цвет линий** открывает палитру выбора цвета. Эти параметры применяются к
  географической сетке, а не к изолиниям поля.

Настройки действуют в быстром просмотре и оформлении, обновляются при навигации
и сохраняются внутри `.ggproject`. Для корректных градусов требуется верная СК
исходных координат. Географическая сетка ограничена 200 линиями на ось и 10 000
крестов; при превышении увеличьте шаг. Для очень крупного шага внутри небольшого
участка может не оказаться ни одной линии или подписанной отметки.

## Теневой рельеф и положение солнца

Выделите карту → **3 · Вид → Теневой рельеф**. Появится круг с солнцем:

1. Нажмите внутри круга или перетащите жёлтое солнце. Положение вокруг центра
   задаёт азимут: 0° — к положительной оси Y, 90° — к положительной X,
   180° — к отрицательной Y, 270° — к отрицательной X. Это направление **на
   источник света**, отсчитанное от севера координатной сетки по часовой стрелке.
2. Расстояние от центра задаёт высоту солнца: центр — зенит (90°), край —
   горизонт (0°). Значения можно точно ввести в числовых полях.
3. **Интенсивность тени, %** регулирует силу наложения от 0 до 100%.
   Перетащите ползунок мышью либо введите точное значение рядом.
4. **Усиление рельефа** подчёркивает уклоны условной поверхности поля.

Положение солнца, интенсивность и усиление сохраняются отдельно для каждой карты
в проекте. При выборе другого слоя его настройки восстанавливаются. Перетаскивание
солнца обновляет отображение с ограничением частоты, чтобы не пересчитывать рисунок
на каждом пикселе движения.

Это локальное освещение по уклонам поверхности значений поля, а не физическая
топография или трассировка теней от удалённых объектов. Значения поля, маска
пропусков, единицы и цветовая шкала не меняются; теневой рельеф влияет только
на визуализацию и экспорт изображения.

## SHP и GeoJSON

Задайте СК проекта → **1 · Карта → Контуры и обрезка → Добавить
SHP / GeoJSON**. Контур появится отдельной строкой с галочкой, которую можно
перемещать, переименовывать и удалять. Векторные координаты преобразуются в СК
проекта при загрузке. Поддерживаются точки, линии, полигоны и составные
геометрии; полигоны показываются контурами без заливки.

Для SHP держите рядом связанные `.shx`, `.dbf`, `.prj`. СК из `.prj` читается
автоматически. Без `.prj` используется СК проекта, о чём программа сообщает
в строке состояния. Включите **Уточнять исходную СК при импорте**, если хотите
выбрать её вручную перед загрузкой. GeoJSON без
явной CRS считается WGS84 (`EPSG:4326`, долгота/широта). Атрибуты SHP/GeoJSON
в таблицу проекта не импортируются.

### СК, параметры проекции и импорт ArcGIS .prj

Окна исходной СК файла, **СК проекта…** и **СК и параметры слоя…** используют
одинаковый редактор. Выберите СК из списка, введите EPSG / PROJ / WKT либо
нажмите **Импорт СК из .prj (ArcGIS)…** и выберите файл. Поддерживаются
ArcGIS/ESRI WKT и OGC WKT; название файла не влияет на прочитанные параметры.
Для SHP связанный `.prj` читается автоматически. При включённой галочке
**Уточнять исходную СК при импорте** его можно заменить другим `.prj` или СК
из списка до подтверждения загрузки.

Под названием СК и методом проекции появятся **все её числовые параметры**.
Состав зависит от выбранного метода: например, у поперечной проекции Меркатора
это широта начала отсчёта, осевой меридиан, масштабный коэффициент, условные
восточное и северное смещения. У других проекций могут появиться стандартные
параллели, азимут и другие параметры. У полей указаны единицы; названия
неизвестных программе параметров показываются так, как их сообщает библиотека
проекций. В географической СК без проекции этих полей нет.

Значения можно менять непосредственно в полях. При выборе другой СК или импорте
другого `.prj` весь набор заново заполняется её параметрами. Система отсчёта,
эллипсоид и единицы берутся из СК и сохраняются при редактировании параметров
проекции. Пользовательская СК сохраняется в проекте `.ggproject`.

Смещения — полные параметры проекции, а не величины, которые нужно вычесть
из X или Y. При одинаковых остальных параметрах переход между двумя значениями
восточного смещения изменяет East на разность «смещение проекта − смещение
источника».

Пример: SHP имеет East = **17 100 000 м**, а карта East = **100 000 м**.
Если данные действительно используют ГСК-2011, зону 17 и отличаются только
зональным префиксом:

1. Откройте **СК проекта…**, выберите `EPSG:20917`, в поле **Условное восточное
   смещение** задайте **500 000 м**, подтвердите.
2. При загрузке карты с координатами без префикса выберите ту же СК и восточное
   смещение **500 000 м**. Чтобы открыть окно при импорте, предварительно включите
   **Уточнять исходную СК при импорте** (также для GRD/ZMAP/DAT/NPZ и XYZ).
3. Нажмите **Добавить SHP / GeoJSON**, выберите SHP. Для его исходной СК задайте
   `EPSG:20917` со стандартным восточным смещением **17 500 000 м**.
4. Подтвердите: точка SHP East = 17 100 000 м получит East = 100 000 м в проекте.

Номер зоны определяет также осевой меридиан. Не выбирайте другую зону лишь
для удаления префикса. Если ваша фактическая зона иная, укажите её реальные
параметры. Программа не угадывает систему координат по величине X.

Для загруженного слоя: выделите его → **СК и параметры слоя…** либо правый
клик → **СК и параметры проекции…**. Здесь задаётся СК **текущих координат слоя**,
после чего они пересчитываются в СК проекта. Если слой уже правильно пересчитан,
повторно задавать ему исходную СК файла не нужно; для исправления ошибочного
импорта удобнее удалить слой и загрузить исходный файл заново. Смена СК проекта
пересчитывает все слои. Проект `.ggproject` сохраняет пользовательскую проекцию.

### Цвет, толщина и заливка SHP/GeoJSON

Выделите векторный слой → **Оформление SHP / GeoJSON…** (либо правый клик →
**Оформление контура…**). Выберите цвет линии по палитре и толщину в пунктах.
Для слоя с полигонами дополнительно доступны **Заливка (FILL)**, цвет заливки
и её непрозрачность (0 % — прозрачная, 100 % — сплошная). Внутренние отверстия
полигонов остаются прозрачными. Для линий и точек заливка не показывается.
Подтвердите **OK**: видимый участок карты сохранится. Оформление относится к
выбранному слою и сохраняется вместе с проектом.

GeoJSON читается встроенными средствами, SHP — лёгкой библиотекой pyshp,
входящей в основную установку. Если проект обновлён через git, обновите зависимости:

```powershell
.\.venv\Scripts\python -m pip install -e .
```

Если после установки программа всё равно сообщает, что `pyshp` недоступен,
сначала проверьте библиотеку в Python, которым запущен GeoGarModel. Новое
сообщение об ошибке показывает полный путь к используемому `python.exe` и
готовую команду установки. Закройте программу, выполните именно эту команду и
запустите приложение тем же Python. Проверка локального окружения проекта:

```powershell
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -c "import sys, shapefile; print(sys.executable); print(shapefile.__version__)"
.\.venv\Scripts\python.exe -m geogarmodel
```

Успешная установка через обычный `python -m pip install -e .` не гарантирует
наличия пакета в `.venv`. Для установки только библиотеки чтения SHP:

```powershell
.\.venv\Scripts\python.exe -m pip install "pyshp>=2.3,<3"
```

После проверки импорта полностью закройте приложение и запустите последней
командой выше. Если `import shapefile` выдаёт ошибку, сохраните её полный текст:
он отличает отсутствие пакета от повреждённой установки или ошибки её импорта.

## Оси и масштабная линейка

Подписи метрических осей — **X, м** и **Y, м**. Для старых карт с неизвестными
единицами отображаются такие же подписи по принятому в приложении метрическому
соглашению; это не конвертация координат. Проверьте единицы в метаданных. Карты
с явно заданными градусами подписываются в градусах, FFT и линейка в метрах для
них недоступны.

На шаге **3 · Вид** включите **Масштабная линейка**. Выберите **м** или **км**,
укажите шаг в выбранных единицах и число делений (1–20). `Авто` подбирает шаг
по текущей ширине видимой области. Например, шаг `1 км` и четыре деления дают
линейку от 0 до 4 км. Смена единиц сохраняет физическую длину: 1000 м = 1 км.
Галочка **Подписывать СК под линейкой** выводит имя и EPSG фактической СК проекта.
Линейка следует за горизонтальным перемещением/масштабированием карты. Если
заданная длина больше видимого охвата, уменьшите шаг или число делений.

Линейка находится **под графиком**, вне области карты. Её начало выровнено по
первой видимой основной риске оси X. Числа линейки показывают расстояния от её
начала, а не абсолютные координаты East. Вертикальное положение рассчитывается
от нижней границы подписи X с небольшим отступом, чтобы элементы не пересекались.

Заголовок блока оформления содержит имя выделенной карты. Длинное имя переносится
на следующую строку. При переименовании в списке редактор имеет увеличенную
высоту, чтобы текст оставался видимым.

Кнопка **«Домой» (домик)** возвращает полный охват всех видимых карт, включая
после оформления увеличенного участка. Колесо мыши над картой приближает и
отдаляет её вокруг позиции курсора. Обычное изменение оформления сохраняет
выбранную область просмотра.

Используется один знак: чёрная заполненная стрелка с буквой **N** справа,
непосредственно над цветовой шкалой с небольшим отступом. Прежний выбор разных
символов удалён. Знак находится над цветовой
шкалой и указывает географический север в центре
текущей области карты, рассчитанный по её CRS. В проекции Гаусса—Крюгера её
наклон может отличаться от вертикали из-за сближения меридианов. Это не магнитный
север. Если CRS не задана или не согласуется с координатами и направление вычислить
нельзя, знак скрывается, чтобы не показывать недостоверное направление.
Проверьте EPSG/параметры проекции и наличие зонального префикса в координате East.

## ArcGIS Float Grid

В разделе **1. Карта** нажмите **Открыть GRD / ZMAP / DAT / NPZ / FLT** и выберите файл .flt.
Одноимённый .hdr должен находиться рядом. Если там же есть .prj, программа возьмёт из него
исходную систему координат. При отсутствии .prj по умолчанию используется СК проекта.
Ячейки NoData отображаются как пропуски.

## Импорт изображения

В разделе **1. Карта** нажмите **Импортировать растр…** и выберите изображение.
Если у него есть привязка GeoTIFF или файл привязки рядом с ним (например, TFW или
PGW), ответьте **Да**. Подтвердите или выберите исходную систему координат.

Для изображения без привязки ответьте **Нет**, выберите исходную СК и укажите
на изображении три или более опорные точки, расположенные не на одной прямой.
Колесо мыши приближает/отдаляет изображение относительно курсора, зажатое
колесо позволяет перемещаться по увеличенному растру. «Показать весь растр»
возвращает исходный охват. Максимум — 100 логических экранных пикселей на
пиксель растра (в 6,25 раза больше прежнего ограничения 16). Вокруг изображения
есть свободная область для перемещения, позволяющая приблизить и центрировать
любой угол. Щелчки вне растра не добавляют опорные точки. Крестик устанавливается
в точном месте щелчка без привязки к центру пикселя; дробные пиксельные координаты
сохраняются без округления, в таблице показываются до шести десятичных знаков.
Масштаб просмотра не изменяет пиксельные координаты опорных точек. Введите координаты X и Y в таблице. Значения можно исправить, а выбранную точку
можно удалить. Кнопка **Готово** рассчитывает аффинную привязку по всем точкам.

Растр приводится к СК проекта и появляется в дереве как отдельный слой. Порядок
слоёв задаёт порядок наложения. Изображение и опорные точки хранятся в проекте.
