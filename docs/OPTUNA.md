# Optuna, CPU/GPU и панель результатов

## Быстрый сценарий

1. Запустите `python -m geogarmodel`. Для знакомства откройте «Данные →
   Открыть синтетический пример» и вкладку «Прогноз и оптимизация».
2. Выберите модель, координаты, признаки, CRS и порядок осей. Для проверки
   на независимых пространственных блоках задайте размер блока в метрах.
3. Выберите CPU или GPU. Классические sklearn-методы показывают только CPU.
   GPU ID — номер устройства с нуля. Это настройка модели, а не sampler Optuna.
4. Включите Optuna, задайте trials (по умолчанию 30), внутренние CV-фолды
   (по умолчанию 3) и необязательный лимит времени в секундах.
5. Оставьте диапазоны `{}` для готового пространства выбранного метода
   или нажмите «Заполнить диапазоны для модели», затем отредактируйте JSON.
6. Нажмите «Обучить и оценить». Панель обновляется после каждого trial;
   лучшие параметры и внешние контрольные метрики появляются после завершения.
7. Экспортируйте Trials CSV, контроль CSV, отчёт JSON и выбранный график PNG.

Для установки всех методов: `python -m pip install -e ".[boosting,neural,geo]"`.
GPU-драйверы и подходящую сборку PyTorch следует установить отдельно по
[официальной инструкции PyTorch](https://pytorch.org/get-started/locally/).
Приложение не меняет драйверы и не устанавливает CUDA автоматически.

## Как устроен подбор

Используются `TPESampler(seed=...)` и `MedianPruner`. Направление — minimize.
Целевая функция — RMSE в исходных единицах глубины по объединённым внутренним
валидационным фолдам: корень из взвешенной по числу точек MSE, а не среднее
значений RMSE. Фолды фиксированы между trials.

Сначала отделяется внешний holdout. Внутри оставшейся обучающей части создаются
GroupKFold (пространственный режим) или перемешанный KFold. Для каждого фолда
заново обучаются медианный imputer, масштабирование признаков и масштабирование
цели. После выбора параметров модель оценивается один раз на holdout, затем
переобучается на всех размеченных данных для дальнейшего прогноза.

Промежуточная RMSE передаётся pruner после каждого фолда. После пяти завершённых
trials слабые trials могут отсекаться, начиная со второго фолда. Это **не**
отсечение отдельных эпох или деревьев. График лучшей CV RMSE монотонно не возрастает,
но не гарантирует улучшение независимой контрольной ошибки.

Trials идут последовательно (`n_jobs=1`) для воспроизводимости и контроля памяти
GPU. Параллельные многопроцессные studies и возобновление из SQLite пока не включены.
Лимит времени проверяется Optuna между trials: выполняющийся trial может закончиться
позже указанного лимита. Кнопка остановки проверяется между фолдами, trials и
перед/после финального обучения; нативное обучение не прерывается принудительно.
При отмене частичная итоговая модель не выдаётся, история уже обработанных trials
доступна для экспорта. Прерванный trial может иметь состояние FAIL в истории Optuna;
статус приложения при этом явно сообщает об отмене.

## Диапазоны и фиксированные параметры

Поле «Параметры · JSON» задаёт параметры модели. «Диапазоны · JSON» задаёт поиск;
при совпадении имени найденное значение заменяет фиксированное.

```json
{
  "max_depth": [3, 5, 8],
  "n_estimators": {"type": "int", "low": 100, "high": 500, "step": 50},
  "learning_rate": {"type": "float", "low": 0.005, "high": 0.2, "log": true}
}
```

Для Ridge: `{"alpha":{"type":"float","low":0.0001,"high":1000,"log":true}}`.
Категории должны быть JSON-скалярами; `null` допустим, если его поддерживает
сам параметр модели. Целочисленные low/high должны быть целыми; для log нужны
положительные границы. Диапазоны не гарантируют физическую или библиотечную
корректность произвольных сочетаний параметров: ошибка trial останавливает study
с сообщением, а не скрывается штрафной оценкой. Параметры `device`, `task_type`,
`device_type`, `devices` и GPU ID зарезервированы за выбором устройства.

Готовые пространства учитывают алгоритм: регуляризация у линейных методов,
глубина/листья/число деревьев у ансамблей, learning rate и регуляризация у бустингов,
width/layers/dropout/learning rate у PyTorch-сетей. У Transformer width должен
делиться на heads; готовые width 32/64/128 совместимы с heads=4.

## Поддержка устройств

| Метод | CPU | GPU |
|---|---|---|
| Linear, Ridge, Lasso, Random Forest, Extra Trees, sklearn boosting, MLP | Да | Нет |
| XGBoost | Да | NVIDIA CUDA, `device=cuda:N`, `tree_method=hist` |
| CatBoost | Да | NVIDIA CUDA, `task_type=GPU`, `devices=N` |
| LightGBM 4.6 | Да | OpenCL GPU-сборка, `device_type=gpu`, ID внутри выбранной по умолчанию платформы |
| ResNet, Transformer | Да | CUDA-сборка PyTorch и доступное `cuda:N` |

GPU-модель при отсутствии подходящей сборки/драйвера выдаёт ошибку. Для XGBoost
после fit дополнительно проверяется конфигурация booster: тихий переход на CPU
считается ошибкой. Для PyTorch доступность CUDA и ID проверяется до обучения.
Для CatBoost/LightGBM доступность проверяет библиотека во время fit.

Optuna TPE, imputation/scaling и табличные данные находятся на CPU. XGBoost может
предупреждать о переносе CPU-данных для GPU prediction через DMatrix; это не
означает переход обучения на CPU. Передачи памяти и небольшие выборки могут
сделать GPU медленнее CPU. GPU-результаты не обещают побитовой воспроизводимости.

Локально проверены три XGBoost trials с внутренней CV на RTX 5060 Ti 16 ГБ:
устройство итогового booster — `cuda:0`; построен прогноз для 1280 синтетических
точек. Это smoke-проверка работоспособности, не бенчмарк скорости или геологической
точности. Остальные GPU-бэкенды на этом оборудовании в данной проверке не запускались.

## Что показывают графики

- «Оптимизация»: trial CV RMSE, лучшее завершённое значение, длительность и таблица.
  PRUNED trials остаются в таблице; кривая сравнивает только COMPLETE trials.
- «Диагностика»: прогноз/наблюдения с линией 1:1, невязки, их гистограмма и loss
  итоговой сети. Loss относится к нормированной цели; он не является контрольной RMSE.
- «Карты контроля»: наблюдения, прогноз, signed residual и абсолютная ошибка
  в контрольных точках. Наблюдения/прогноз имеют общую палитру; signed residual —
  симметричную около нуля. Цветовая шкала предполагает глубину в метрах.
- «Параметры»: найденные значения и зависимость внутренней CV RMSE от параметра.

Карты контроля — точечные. Кнопка «Невязки → карта» создаёт отдельно линейно
интерполированный слой; это наглядное представление, не дополнительные наблюдения.
Графики ограничивают отображение до 25 000 равномерно выбранных по индексу точек;
внешние метрики и CSV рассчитываются по всей контрольной выборке.

## Производительность и экспорт

PyQtGraph переиспользует кривые и обновляет их через Qt-сигналы. Обучение идёт в
QThread; вычисления не вызывают Qt-рисование из рабочего потока. История обновляется
по trials, а не по каждой итерации нативной модели. Графики экспортируются PNG
шириной 1800 пикселей. Для регулярных карт доступны PNG/PDF/SVG через toolbar.

Отчёт JSON содержит seed, индексы внешнего разбиения, параметры, best CV RMSE,
устройство, лимиты, историю trials, фолдовые RMSE и версии NumPy/sklearn/Optuna.
Trials CSV содержит длительности, состояния, параметры и best-so-far.
CSV наблюдений/прогнозов/невязок экспортируется без сокращения точек.
