# GeoGarModel 2.3: руководство

Начальные воксельные модели, UBC/VTK/Geosoft, математические операции и обрезка
по поверхности описаны в [редакторе начальной модели](INITIAL_MODEL.md).

## Импорт поля и условия расчёта трансформант

Таблица, загруженная как обучение/прогноз на ML-вкладке, не становится картой.
На вкладке карт используйте «Таблица XYZ → регулярная сетка»: текущий импорт берёт
первые два столбца как координаты и **третий столбец как единственное поле**.
Подготовьте XLSX/CSV с заголовками X, Y, поле. Остальные признаки не рассчитываются
пакетно. Точки интерполируются линейно на сетку 200×200; вне выпуклой оболочки
остаются пропуски. CRS и порядок X/Y берутся из настроек таблиц на ML-вкладке:
по умолчанию X — север, Y — восток. Проверьте их перед импортом.

После импорта ZMAP выберите слой и откройте «CRS и единицы карты…»: укажите
фактическую зону/CRS, координаты **m**, единицы поля (например mGal или nT).
Сам ASCII ZMAP в текущем импорте этих метаданных не предоставляет. Выбор CRS
описывает координаты файла, а не перепроецирует их.

Расчёт требует регулярной сетки в метрах. Производные и продолжение вверх
вычисляются через 2D FFT: множители ikx, iky, k, k² и exp(−kh) соответственно,
где k = sqrt(kx² + ky²), а вертикальная производная положительна вниз.
Пропуски временно заполняются ближайшими узлами, сетка отражается по краям
на 25% размера с каждой стороны; после обратного FFT исходная маска восстанавливается.
Горизонтальный градиент, аналитический сигнал и Tilt объединяют производные.
Полиномиальный тренд рассчитывается отдельно методом наименьших квадратов.
Параметр длины волны относится к гауссову фильтру, высота — к продолжению вверх.

Текущее ограничение: если пусто более 50% узлов, расчёт отклоняется. Штатный
`Zmap_2.dat` (447×486) имеет лишь около 21% заполненных узлов. Даже обрезка до
рамки данных оставляет около 31% заполнения: требуется более локальная рабочая
область или заранее подготовленная сетка. Ближайшее заполнение и отражение не
устраняют краевых артефактов, особенно у производных. Автоматическая обработка
больших нерегулярных масок и выбор произвольного столбца XLSX пока не реализованы.

## Оформление окна Windows

На Windows 11 заголовок, текст и тонкая граница окна используют тёмную палитру
через [официальный DWM API](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute).
Запрашиваются скруглённые углы; их отображение определяет Windows. Системные кнопки,
Snap и изменение размера сохраняются. На неподдерживаемых системах остаётся
стандартная рамка. Общесистемная тема не изменяется.

## Установка и структура

Python 3.11–3.13; Windows — основная платформа. Запуск из корня checkout:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
python -m geogarmodel
```

Linux/macOS: активация `source .venv/bin/activate`. Optional extras:
`boosting` (XGBoost, LightGBM, CatBoost), `neural` (PyTorch; GPU зависит от установленной сборки),
`geo` (GeoPandas для SHP/GeoJSON). Недоступные optional-модели не показываются
в списке; после установки перезапустите приложение. Размер загрузки PyTorch
существенен. Базовый MLP доступен без него.
LightGBM закреплён на 4.6.0: при проверке 4.7.0 обнаружен нативный access violation
в полном наборе Windows-тестов; на 4.6.0 тот же набор проходит.

`grids.py` — чтение и сетки; `coordinates.py` — CRS; `fields.py` — вычисления;
`models.py` — обучение; `neural.py` — сети; `optimization.py` — Optuna;
`compute.py` — CPU/GPU; `plotting.py` — карты; `dashboard.py` — PyQtGraph;
`theme.py` — оформление; `app.py` — PyQt5. Ядро можно импортировать без запуска Qt.
Notebook 1.1 сохранён, но не используется новым приложением.

Для быстрого знакомства: меню «Данные → Открыть синтетический пример» создаёт
поле силы тяжести, 320 точек обучения и прогнозную сетку. Это искусственные
данные для проверки работы интерфейса, не геологический эталон качества.

## Координаты ГСК-2011

В форме прогноза выберите CRS; ГСК-2011 / Gauss-Kruger 6° берутся из установленной
базы PROJ, а не из вручную составленного списка. Зона 10 — EPSG:20910, зона 25 —
EPSG:20925. Для иных проекций можно ввести EPSG вручную. Выбор CRS означает
назначение метаданных, а не преобразование численных координат.

У таблиц по умолчанию X=Northing (север), Y=Easting (восток). Флажок порядка
управляет переводом таблицы в карту; экспорт прогноза сохраняет названия и порядок
координат исходной таблицы. У карты горизонтальная ось x=Easting, вертикальная
y=Northing. Производная X в модуле сеток означает именно производную по восточной
оси карты. Не смешивайте точки разных зон в одной таблице: предварительно
перепроецируйте их в единую метрическую CRS.
Старые примеры `Train1.xlsx`/`Test_1.xlsx` используют X около 500000 и Y около
8000000: для их отображения снимите флажок «X = север, Y = восток» и назначьте
их действительную исходную CRS. Новая программа не может восстановить CRS
старого файла только из численных координат.

XYZ-импорт использует первые три столбца и настройки CRS/порядка осей из вкладки
прогноза. ZMAP обычно не содержит CRS: задайте её и единицы в «CRS и единицы карты».
Список зон относится к 6° Гауссу—Крюгеру, не к GSK 3GK (3°).
См. [определение OGC EPSG:20910](https://opengeospatial.github.io/ontology-crs/data/def/crs/EPSG/0/20910/).

## Прогноз глубины одного горизонта

1. Загрузите XLSX или CSV с заголовками. По умолчанию первые два столбца —
   координаты, последний — глубина, остальные — признаки потенциальных полей,
   сейсморазведки и другие численные атрибуты. Можно выбрать столбцы вручную.
2. Выберите признаки, CRS, размер пространственного блока в метрах, seed,
   долю контроля и метод. Цель и координаты исключены из признаков.
3. При необходимости введите параметры JSON, например для Random Forest:
   `{"n_estimators": 500, "min_samples_leaf": 3}`.
4. Для подбора включите Optuna, выберите CPU/GPU, число trials, CV-фолдов и лимит
   времени. Диапазоны можно оставить `{}` (готовые для метода) или задать JSON,
   например `{"max_depth": [5, 10, null]}`. Поиск TPE минимизирует RMSE по внутренним
   фолдам. Подробности и примеры — [OPTUNA.md](OPTUNA.md).
5. Нажмите «Обучить и оценить». Получите MAE, RMSE, MSE и R² на отдельном контроле.
   После оценки итоговый конвейер обучается на всех размеченных точках.
6. Загрузите прогнозную таблицу с теми же именами признаков и координат.
   Порядок столбцов может отличаться. Нажмите «Прогнозировать».
7. Экспортируйте прогноз, контрольные наблюдения/прогнозы/невязки CSV и отчёт JSON
   с параметрами, историей Optuna, составом признаков, индексами разбиения и версиями библиотек.
   «Прогноз → карта» интерполирует точки в сетку 200×200 без линейной экстраполяции
   за выпуклую оболочку наблюдений.

Пропуски в признаках заменяются медианами обучающей части. Пропуски глубины,
координат, Inf и полностью пустой обучающий признак вызывают ошибку.
StandardScaler признаков и цели обучаются внутри каждого фолда. Прогнозная
площадь не участвует в оценке медиан и масштабов. Отчёт содержит метрики
контрольной модели, тогда как прогноз выполняет модель на всех размеченных данных.

Пространственные блоки не пересекаются между обучением и контролем. Они не создают
буферное расстояние: по краям соседних блоков точки могут быть близки. Выбирайте
размер блока с учётом корреляционного радиуса и дополнительно проверяйте на
независимой площади/профиле. При сравнении нескольких методов сохраняйте одинаковые
seed/разбиение; многократный выбор метода по одному контролю требует третьего,
независимого набора для итоговой оценки. Отрицательный R² допустим и означает,
что прогноз хуже постоянного среднего контрольной цели.

MLP — (128,64,32). ResNet — residual MLP с LayerNorm и GELU. Transformer создаёт
отдельный обучаемый токен для каждого численного признака, применяет attention
между признаками и агрегирует токены. Он не моделирует последовательность трасс
или пространственные окна. Пример параметров обеих PyTorch-сетей:
`{"epochs": 100, "width": 32, "layers": 2, "batch_size": 128}`.
У Transformer `width` должен делиться на `heads` (по умолчанию 4). Обучение идёт
фиксированное число эпох без использования внешнего контроля для early stopping.
Эти методы требуют проверки на ваших данных; превосходство над бустингами не
предполагается. Сейсмические атрибуты поддерживаются как табличные признаки;
чтение SEG-Y и обучение на сырых сейсмокубах сюда не входят.

## Карты

ZMAP+ ASCII читается с фиксированной шириной поля; колонки идут с севера на юг.
Пустые значения становятся NaN. NPZ сохраняет данные, координаты, единицы, CRS
и историю обработки. XYZ-импорт усредняет дубликаты координат, интерполирует
линейно, не заполняет точки за выпуклой оболочкой. В API доступны также nearest/cubic.
Нерегулярные наблюдения перед FFT обязательно приводятся к регулярной сетке.
Для сеток с большими пустыми полями увеличьте нужный участок инструментом Zoom
и нажмите «Обрезать по текущему виду карты» — появится отдельный слой.

Доступны линейная шкала, 2–98 процентили, симметричная около нуля, ручные пределы,
изолинии и отмывка. Отмывка — только визуальный слой. Векторные границы сохраняются
при смене палитры и перепроецируются в CRS текущей карты через GeoPandas.
Pan/Zoom/Home и сохранение PNG/PDF/SVG доступны в Matplotlib toolbar.
Регулярные сетки отображаются через растровый `imshow`; при смене палитры
переиспользуются изображение и цветовая шкала. Изолинии больших сеток строятся
на представлении до 512×512 узлов. Это ограничение отображения, не FFT и экспорта.
Интерактивная панель результатов использует PyQtGraph: историю Optuna, стоимость
trials, параметры, crossplot, гистограмму невязок, loss сети и карты контроля.
Отображение точечных графиков ограничено 25 000 точками; расчёты и CSV используют
все точки. На картах контроля координатные подписи показывают километры от
указанного начала E/N; численные координаты в подсказках и экспорте остаются в метрах.

## Трансформанты и региональное/локальное поле

Все операции создают новый слой. Оси сетки возрастают, шаг постоянен;
FFT рассчитывается только для плоских координат в метрах. Поле может быть в mGal,
nT и других согласованных единицах. Для интерпретации используйте данные на
единой высотной поверхности: сами фильтры не выполняют leveling наблюдений.

Пусть `kx=2π fx`, `ky=2π fy`, `k=sqrt(kx²+ky²)` (радианы/метр):

| Операция | Вычисление |
|---|---|
| X, Y | спектральные множители `i kx`, `i ky` |
| Z, ZZ | множители `k`, `k²`; Z положителен **вниз** |
| Горизонтальный градиент | `sqrt(dx²+dy²)` |
| Аналитический сигнал | `sqrt(dx²+dy²+dz²)` |
| Tilt | `atan2(dz, sqrt(dx²+dy²))`, радианы |
| Продолжение вверх | `exp(-k h)`, высота `h ≥ 0` |
| Региональное поле | продолженное вверх поле или полином 1–3 степени |
| Локальное поле | исходное поле минус выбранное региональное |
| Gaussian low-pass | `exp(-0.5 (k λ / 2π)²)`; λ — масштаб, передача e^(-1/2) на волне λ |
| Gaussian high-pass | исходное поле минус low-pass |

Полиномиальный тренд оценивается по конечным узлам методом наименьших квадратов
после приведения координат к [-1,1]. Для FFT среднее вычитается и восстанавливается
только для low-pass/продолжения вверх. По умолчанию применяется отражённое
дополнение по 25% размера с каждой стороны. Пустоты временно заполняются ближайшим
конечным значением, исходная маска восстанавливается. При >50% пустот операция
отклоняется. Это численное заполнение может влиять на соседние узлы: избегайте
интерпретации границ масок и краёв карты. Параметр `pad=0` API предназначен в том
числе для проверки периодических синтетических полей.

Аналитический сигнал, горизонтальный градиент и tilt помогают выделять границы
источников, но не являются автоматически построенными геологическими разломами.
Разделение на региональное/локальное зависит от масштаба: сравнивайте несколько
высот продолжения и степеней тренда, сохраняйте историю и исходное поле.

Реализованы общепринятые операции, аналогичные отдельным фильтрам Oasis montaj;
численная идентичность коммерческой программе не заявляется. Параметры подготовки
краёв и заполнения пустот могут отличаться. См. официальные материалы:
[аналитический сигнал](https://help.seequent.com/Oasismontaj/2026.1/Content/gxhelp/g/gridasig_gx.htm),
[продолжение поля](https://help.seequent.com/Oasismontaj/2025.2/Content/gxhelp/f/fftcont_gx.htm),
[PyTorch TransformerEncoderLayer](https://docs.pytorch.org/docs/stable/generated/torch.nn.TransformerEncoderLayer.html).

## Проверки и дальнейшая миграция

`python -m pytest -q` проверяет знаки/амплитуды производных на гармоническом поле,
ослабление гармоник при продолжении, восстановление регионального+локального,
полиномиальные тренды, маски, ориентацию ZMAP, roundtrip NPZ, пространственное
разбиение, схемы признаков, доступные модели и создание Qt-карты без экрана.
Optional-сети проверяются при наличии PyTorch. CI также ставит boosting/neural.

Hyperopt и GridSearchCV заменены Optuna; старый notebook сохранён как архив.
Не перенесены старые отдельные окна SHAP/Plotly, сохранение обученной
ML-модели между запусками, SEG-Y, интерактивное построение профилей и совместная
инверсия двух полей. Приведение к полюсу/экватору и продолжение
вниз требуют отдельного выбора физической модели и стабилизации; здесь их нет.
Это границы текущей реализации, а не пункты, которые уже можно вызвать в меню.
Для нескольких горизонтов пока выполняйте отдельное обучение для каждого;
ограничения непересечения горизонтов не навязываются.
Доступен [отдельный модуль 3D-плотностного моделирования, моделирования магнитной
восприимчивости и намагниченности](INVERSION.md). Прежняя межслойная постановка снята с плана из-за
отсутствия входных данных. Руководство нового модуля описывает его отличия от GravMagInv3D.
